# Регламент разработки (Contributing Guidelines)

---

## 1. Модель ветвления (GitFlow)

В проекте используется модель GitFlow.

### Основные ветки

- **`main`** — стабильная ветка, содержит только релизный код. Прямые коммиты запрещены.
- **`develop`** — ветка интеграции, куда сливаются готовые фичи. Прямые коммиты запрещены.

### Ветки для разработки

- **`feature/<номер_задачи>_<краткое_описание>`** — для новых функций.
  - Пример: `feature/IC-01_teamlead_initial_setup`
- **`hotfix/<описание>`** — для срочных исправлений в `main`.
- **`release/<версия>`** — для подготовки релиза.

### Правила

1. Все изменения вносятся только через Merge Request (Pull Request) в ветку `develop`.
2. Ветка `main` обновляется только через `release/*` или `hotfix/*`.
3. Имя ветки должно содержать номер задачи из трекера.

---

## 2. Conventional Commits

Все коммиты оформляются по [стандарту](https://www.conventionalcommits.org/)

---

## 3. Процедура Merge Request (Pull Request)

1. Создать ветку от `develop`.
2. Выполнить задачу, сделать коммиты по стандарту.
3. Запушить ветку в удалённый репозиторий.
4. Создать Pull Request в `develop`.
5. В описании PR указать:
    - Ссылку на задачу из трекера (например, `Closes #IC-01`)
    - Список выполненных действий
6. После одобрения Team Lead — слить PR в `develop`.
7. Перевести задачу в трекере в статус «Готово».

--- 

## 4. Code Review

- Team Lead проверяет каждый PR: корректность имени ветки, стиль коммита, наличие описания.
- При замечаниях — оставляет комментарии, PR возвращается на доработку.
- После одобрения — PR сливается в `develop`.
